# Review checklist

Mark each applicable item **Pass** or **Fail** and point to its location in the brief. A truthful unknown can pass an evidence-integrity check while leaving the recommendation provisional. Use **Not applicable** only with a scope reason, such as a copy-only task with no experiment requested. Repair failed applicable items before treating the output as ready.

## Pass/fail criteria

| Check | Pass condition | Fail condition |
| --- | --- | --- |
| Scope | Deliverable and objective match the request | An unsolicited research or publishing project replaces the task |
| Buyer selection | Recent actual buyer or current buying participant, with relevance explained [S1][S2] | Demographic fit is treated as buying evidence |
| Behavior sequence | Concrete actions and timing, or gaps openly recorded [S2] | Future intentions and opinions are written as actions |
| Evidence integrity | Claims have ledger IDs; inference and uncertainty remain visible | Invented quotes, concealed contradictions, or unsupported certainty |
| Trigger | What changed readiness is distinguished from seller discovery [S1] | An impression or generic funnel stage stands in for a trigger |
| Primary job | Situation and progress explain the purchase [S1] | A feature list or job title substitutes for motivation |
| Alternatives | Actual approaches include workarounds where relevant [S8] | Only vendors familiar to the seller appear |
| Personal desire | Supported by the story or explicitly unknown [S1] | Emotion is assigned because it helps the copy |
| Psychological fit | Presentation addresses an evidenced barrier | Several named biases are stacked without a reason |
| Buyer language | Actual language is traceable; draft wording is labelled [S3] | Composite or invented wording is presented as a testimonial |
| Credibility | Proof is true, relevant, and scoped to the promise [S5] | Credentials, outcomes, scarcity, or endorsements are invented |
| Belief update | Buyer can revise a view without being insulted [S4] | Copy humiliates the buyer for using the current approach |
| Curiosity | Topic matters to the buyer and the promised answer appears [S6] | Hook conceals the topic or never delivers |
| Pain and relief | Cost is proportionate and a credible next step follows [S7] | Fear is exaggerated or relief is unsupported |
| Buyer relevance | A first encounter explains what improves for the reader [S8] | Brand self-congratulation assumes existing attention |
| Sensitive purchase | Documented anxiety is reduced when relevant [S8] | Copy introduces stigma unsupported by the evidence |
| Test alignment | Buyer, moment, channel, offer, promise, and CTA connect [S1] | Channel choice follows fashion or assumed reach |
| Team choice | Story comes first; three candidates and one first test where relevant [S1] | Several campaigns launch without a learning priority |
| Test specification | Measure, denominator, comparison, period, limits, and learning question are clear | Clicks are mistaken for demand or success cannot be evaluated |
| Outcome honesty | Drafts, hypotheses, and observed results are distinguished | A prepared test is described as successful or causal without data |
| Attribution | [S#] points to a fetched source in ../references/sources.md | Missing sources or package conventions attributed to Bourgoin |

Evidence and experiment specifications are package review conventions. The cited rows apply the public guidance described in ../references/method.md.

## Common failure modes and fixes

| Failure mode | Fix |
| --- | --- |
| Persona full of demographics | Recover the recent buying sequence and choose a situation that explains action. [S1][S2] |
| Interview becomes a wish list | Ask what the person recently did, tried, paid for, or abandoned. [S2] |
| Attractive but invented emotional story | Remove the invented motive, mark it unknown, and identify a follow-up question. |
| Feature-heavy message | Lead with the job and progress; use features to explain how the promise is supported. [S1] |
| Rival list ignores the status quo | Ask how the buyer got the job done before searching. [S8] |
| Team jargon replaces buyer language | Gather distinctive phrases and test their clarity with the intended audience. [S3] |
| Buyer blamed for the old approach | Explain changed circumstances or a respectful learning path. [S4] |
| Impressive but irrelevant proof | Replace it with evidence of the capability needed for this buyer's job. [S5] |
| Clickbait with no answer | State a relevant question and deliver the answer in the content. [S6] |
| Fear without feasible relief | Narrow the problem to a supported cost and explain the practical next step. [S7] |
| False countdown or invented scarcity | Remove it; use a real buyer moment or verified offer condition if relevant. |
| Too many tests at once | Select one first experiment and state what it can teach. [S1] |
| Small sample described as a market truth | Report scope and uncertainty; gather more stories or behavior before generalizing. |
| Changed channel, offer, and copy called a headline test | Describe it as a campaign-concept test or keep material variables comparable. |
| High click rate declared a buying win | Evaluate the original objective and track qualification or purchase behavior. |

## Release decision

Record unresolved failures, their impact, and the smallest repair. Deliver a provisional brief when evidence gaps remain but the work is still useful. Do not hide those gaps inside polished copy. Execute only actions within the user's authorized scope. Revisit the ledger and hypothesis after results arrive rather than retrofitting the story to make the recommendation look correct.
