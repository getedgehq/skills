# Homepage Positioning Review Checklist

Use this after completing the brief and wireframe. Record Pass or Fail for each applicable row and give supporting evidence or a concrete correction. Conditional rows can be marked Not applicable with a reason. Missing customer review is a pending validation task, never a reported pass.

These review gates operationalize the public method; they are not a published certification rubric. Method citations explain the rule. Product evidence must come from the assignment's E records.

## Common failure modes and fixes

| Failure | Fix |
| --- | --- |
| A broad ICP consists only of industries and headcount | Start with the owned activity and solution state, then add justified company filters. [S5] |
| The message targets the signer while the champion cannot recognize their task | Write the primary story for the reachable initiator; provide approver material separately. [S6] |
| An M3 page explains why the buyer should start doing work they already do | Replace basic education with the specific incumbent constraint and reason to switch. [S5] |
| A catchy H1 could fit nearly any software company | Add the category or exact job and a concrete relevant difference. [S4] |
| Value sections promise only efficiency or revenue | Show the feature and enabled activity, then the immediate removed limitation. [S8] [S9] |
| Scores appear authoritative despite weak inputs | Add evidence and rationale; mark uncertainty and choose on credible fit rather than totals alone. [S9] |
| Several headlines are presented as several strategies | Vary champion, task, comparator, reference point, or route and explain the implications. [S1] |
| A platform label bundles unrelated responsibilities | Find a genuine shared job, present a suite, or lead with the strongest recognized product. [S7] |
| A narrow message is diluted to include every use case | Restore the selected argument and put secondary needs on dedicated paths. [S9] |
| Source citations are used to prove the user's product claim | Replace with E evidence; remove or qualify the claim when evidence is unavailable. |
| Copy polishing conceals a strategic mismatch | Return to the audience, comparator, or anchor decision and update the record and page together. [S1] |
| Higher conversion is promised as the direct result | Promise clearer explanation; assess commercial outcomes in the wider acquisition and product context. [S9] |

## Review outcome

**Ready:** Applicable desk-review gates pass and public claims have product support. State any pending human validation separately.

**Provisional:** The brief is useful but a strategic assumption or important validation remains unresolved. Name what could change the recommendation.

**Revise:** A failure changes the audience, comparator, scope, mechanism, or hero reference point. Repair that decision before treating the copy as ready.

Finish with the status, failed gates, required fixes, and pending questions. A desk review does not establish customer demand or measured performance.
