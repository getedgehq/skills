# Message decision skeleton

Fill with the user's options and facts. The finished output is the decision page; keep the evidence status, buyer-context gaps and claim audit in your head. The clarity-relevance-value-differentiation order and buyer-panel testing follow Laja's public Wynter material [S1] [S3] [S4]; the layout is a package convention.

**Recommendation:** [which message to go with, in one or two sentences, and the main reason a target buyer would get it]

**How each option reads to a buyer** (a few bullets each)
- Option [A]: [clear? relevant? valuable? different from what they use now? where it first breaks]
- Option [B]: [...]

**The message to use:** [the chosen option, revised to fix its earliest weak layer: headline + one supporting line, and proof if the input has it]

**How to decide** (when the team must still decide or asked how): [who to recruit from the target segment and how, within their budget and timeline; about 15 people per message for a qualitative read; the exact neutral questions (what is this, who is it for, how clear / relevant / different, why); cost; the decision rule that picks the winner; arithmetic checked]

**Claims to hold back:** [any claim in the options the input does not substantiate, one line each]

## Page review variant

Diagnosis in a few bullets, ordered by the earliest failing layer, then the rewritten copy for the failing sections.
