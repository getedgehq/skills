# Review Checklist

Review the finished brief against [the method](../references/method.md). Mark every item PASS or FAIL and record the evidence or correction. Conditional items may pass with an explicit, justified not-applicable note. This is a package review tool, not Meier's published scoring instrument.

## Pass/fail checks

- [ ] **Decision:** PASS if the brief identifies one outcome, affected segment, observed friction, changeable lever, and decision owner. FAIL if it merely proposes becoming more relevant to Gen Z. [S4]
- [ ] **Segmentation:** PASS if relevant life stage, context, needs, and exclusions are explicit. FAIL if age alone stands in for behavior or a universal persona.
- [ ] **Evidence status:** PASS if behavior, participant accounts, hypotheses, and method guidance are distinguishable with provenance and limitations. FAIL if imagined findings appear as completed research. [S3]
- [ ] **Direct participation:** PASS if affected people influenced interpretation or options, or the brief is clearly provisional with a recruitment plan. FAIL if executives' children or one symbolic young reviewer are treated as the whole audience. [S2] [S6]
- [ ] **Contrasting experiences:** PASS if the brief includes useful variation and addresses counterexamples or missing perspectives. FAIL if only enthusiastic current insiders support a broad conclusion.
- [ ] **Offer diagnosis:** PASS if an employer brief inspects money, internal appreciation, and external appreciation, or another branch diagnoses its actual benefit and experience. FAIL if a slogan substitutes for diagnosing the offer. [S4] [S7]
- [ ] **Model integrity:** PASS if Love-Job is attributed to Meier and Dietrich, used for employer diagnosis, and has no invented validated scores. FAIL if the brief claims a proprietary questionnaire or universal weighting. [S7]
- [ ] **Responsibility and support:** PASS if proposed contribution has scope, resources, feedback, and decision boundaries. FAIL if responsibility is ceremonial or unsupported. [S5] [S6]
- [ ] **Mentoring, if proposed:** PASS if enrollment is voluntary, matching considers personal fit, goals are reciprocal, a sequence is defined, and senior participation is visible. FAIL if mandatory junior instruction is presented as Meier's method. [S5] [S8]
- [ ] **Mentoring attribution:** PASS if a changed duration is identified as an adaptation and original prompts are used. FAIL if the brief claims to reproduce ZEAM's proprietary cards or program. [S8]
- [ ] **Communication, if proposed:** PASS if channel choices follow current segment evidence, claims match verified conditions, and continuing activity has capacity and ownership. FAIL if dated platform advice or youthful language is the only rationale. [S4] [S7]
- [ ] **Options:** PASS if the recommendation explains a meaningful comparison and tradeoffs, including participant contributions. FAIL if the selected tactic is detached from the findings.
- [ ] **Test:** PASS if comparison, baseline, outcome definition, period, participant feedback, and scale/revise/stop conditions are clear. FAIL if views alone are treated as recruitment, adoption, or retention success. [S6] [S9]
- [ ] **Interpretation limits:** PASS if the evidence supports the claim's breadth and certainty. FAIL if small, selected, uncontrolled evidence is called representative or causal.
- [ ] **Ownership:** PASS if every proposed change has an owner, next action, dated review, and relevant dependencies. FAIL if the organization cannot tell what to do next.
- [ ] **Attribution:** PASS if Meier-specific claims cite matching sources and package tools are identified as such. FAIL if an inference is presented as a named Meier framework. [S1] [S7] [S8]

## Review outcome

**Ready for a bounded pilot:** All applicable items pass, including evidence, promise integrity, capacity, and test design.

**Ready as a provisional discovery brief:** Evidence gaps are explicit, claims remain hypotheses, and the recruitment and evidence plan is actionable. This status is not validation for broad implementation or external promises.

**Needs revision:** Any failed item remains. Record the failing item, exact defect, correction owner, and review date. Do not average pass/fail items into an attractiveness score.

## Common failure modes and fixes

| Failure mode | What to change |
| --- | --- |
| A single universal Gen Z persona | Define the decision-specific segment; seek contrasting experiences and note variation |
| Managerial family anecdotes presented as research | Mark hypotheses and recruit affected people directly [S2] |
| Interviews conducted after the solution is fixed | Allow participants to reinterpret themes and change at least the feasible choices [S3] |
| A purpose slogan compensating for weak conditions | Diagnose money, internal treatment, and reputation; revise unsupported promises [S7] |
| Young people consulted but denied meaningful contribution | Specify an actual task, support, and decision boundary [S5] [S6] |
| Mandatory or one-way reverse mentoring | Use volunteers, personal fit, reciprocal goals, structure, and participating senior leaders [S5] [S8] |
| One intern used to certify an entire market | Broaden participation or label the limited perspective and remaining gaps [S6] |
| Platform choice copied from an old summary | Gather recent journey evidence; treat historical advice as context [S2] [S4] |
| Viral content masking a product or hiring problem | Test the underlying offer or process and connect content to a verified improvement [S4] [S7] |
| Views treated as business success | Define the relevant conversion, quality, retention, or use outcome and its denominator [S9] |
| Promotional results adopted as promised returns | Remove guarantees; set a contextual pilot target and measurement limits [S4] [S9] |
| Invented survey, score, or proprietary conversation cards | Use clearly identified package tools and original prompts; preserve the public-source boundary [S7] [S8] |
| A polished strategy despite unavailable participants | Deliver a provisional brief with recruitment criteria, questions, and a validation decision |
| A recommendation with no authority or resources | Name dependencies, obtain the owner's decision through the user's authorized workflow, and narrow the pilot to feasible work |
