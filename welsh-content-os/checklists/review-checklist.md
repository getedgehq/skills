# Review checklist

Mark each applicable item **PASS** or **FAIL** and name the affected asset. Use **N/A** only with a reason, such as a single-post assignment without a hub. These are package review gates derived from the cited public principles, not a verbatim Welsh checklist. Repair failures before describing the package as ready. Unavailable metrics and future publication results are not failures when disclosed accurately.

## Brief and evidence

- [ ] PASS / FAIL: The intended reader has a specific recognizable problem, and each opening supplies enough topic and relevance context. [S5]
- [ ] PASS / FAIL: The cycle's scope, main channel, and primary objective are explicit; a new system has a sustainable starting point. [S1][S10]
- [ ] PASS / FAIL: Important claims have supplied evidence or a defensible explanation. Invented examples are labelled; there are no fabricated achievements or testimonials.
- [ ] PASS / FAIL: Reused patterns contain the writer's own reasoning and wording. AI suggestions have been reviewed and personalized. [S1][S8]

## Hub and spokes

- [ ] PASS / FAIL: The hub teaches a substantial lesson with concrete actions or examples before any offer. [S2][S3][S9]
- [ ] PASS / FAIL: Each spoke delivers a usable independent takeaway and is traceable to a hub lesson when a hub is in scope. [S3]
- [ ] PASS / FAIL: The batch varies angle, evidence, or treatment; it does not repeat the same payoff in slightly different words. [S3]
- [ ] PASS / FAIL: The chosen count fits the substance and user request. The optional 1-3-5 model is counted correctly and does not force unwanted formats. [S1][S3]
- [ ] PASS / FAIL: The opening promises what the body delivers. Terminology is understandable to the actual audience. [S4][S5]
- [ ] PASS / FAIL: The ending supports one primary job. Discussion questions invite a specific experience or decision. [S4][S6]
- [ ] PASS / FAIL: Channel adaptation changes relevant context or presentation. Welsh's personal formatting preferences are treated as hypotheses. [S6][S10]
- [ ] PASS / FAIL: Evergreen assets have plausible lasting relevance; timely assets are dated and excluded from automatic evergreen reuse. [S10]

## Distribution and learning

- [ ] PASS / FAIL: Every link invitation identifies the relevant issue or article rather than an unrelated homepage. Missing destinations are flagged. [S9]
- [ ] PASS / FAIL: Previews provide value, follow-ups add distinct substance, and any related-content loop helps the reader continue learning. [S1][S7]
- [ ] PASS / FAIL: Any offer exists, is relevant, and follows useful education; a commercial action has not been invented for an educational brief. [S9]
- [ ] PASS / FAIL: Draft, scheduled, and published statuses reflect evidence. Outlines and scripts are identified as such.
- [ ] PASS / FAIL: Metrics match the asset's job, include publication dates and observation windows, and distinguish missing data from zero. [S6][S9]
- [ ] PASS / FAIL: The next test uses the writer's own audience. Likes are not equated with completion, and correlation is not claimed as causal proof. [S6]
- [ ] PASS / FAIL: A workflow improvement considers elimination and simplification before automation and delegation. [S11]

## Common failure modes and fixes

| Failure | Fix |
| --- | --- |
| A striking headline with no defensible lesson | Write the teaching and example first; then choose a truthful opening. [S4] |
| Insider terminology before reader context | Name the recognizable problem or explain the term where it first appears. [S5] |
| A thin hub multiplied into many posts | Add reasoning, steps, and evidence, or reduce the assignment to a stronger single asset. [S2][S3] |
| Fifteen repetitive derivatives to complete a quota | Keep the strongest independent angles; adapt format and count. [S3] |
| Unedited AI voice or borrowed achievements | Reject unsupported claims and rebuild with the writer's knowledge and experience. [S8] |
| Every channel launched at once | Focus on a workable primary channel while retaining reuse ideas. [S10] |
| A vague request for opinions | Ask about a specific obstacle, choice, or experience that the post explains. [S6] |
| Competing requests to comment, follow, subscribe, and buy | Choose the asset's main job; remove distracting invitations. |
| Topic-specific post linked to a homepage | Use the exact matching article or flag the destination as pending. [S9] |
| A preview that conceals all value | Reveal a useful lesson and explain what the full piece adds. [S1] |
| Treating one high-impression post as a universal format | Compare patterns across the writer's own posts and record a testable hypothesis. [S6] |
| Treating likes as proof of reading or sales | Separate proxy signals from verified clicks, subscriptions, and purchases. [S6][S9] |
| Automating a cumbersome, unstable process | Remove unnecessary steps, simplify, then document the stable handoff. [S11] |

## Handoff rule

State the reviewed scope, material repairs, and remaining blockers. A package with unresolved facts or URLs may be ready for editorial review but is not ready for publication. Preserve the user's requested deliverable size and external-action permissions.
