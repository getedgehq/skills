# Pass/fail production review

Use at brief approval, footage acceptance, and final delivery. Record reviewer, date, artifact version, and evidence for every applicable row. PASS means the condition is visibly met. FAIL requires a specific fix and owner. Use N/A only with a reason. A failed applicable condition keeps the affected handoff pending; an incomplete result does not become a performance winner.

These are package acceptance criteria derived from the method, not a verbatim Savannah checklist. Citation keys resolve in [../references/sources.md](../references/sources.md).

## Brief gate

| Pass/fail condition | Evidence to inspect |
| --- | --- |
| Strategist, creator, and editor are distinct people on this ad | Named role contract [S1] |
| Audience, buying situation, objective, and destination are specific | Intake and concept brief |
| Concept connects one customer motivation to a supported benefit | Script and claim evidence |
| Inspiration is linked and distinguished from account performance | Library entry and results record |
| First frame, opening action, exact hook wording, and benefit bridge are defined | Variant table |
| Visual variations alter footage, action, framing, or performance rather than only captions | Opening storyboard [S5] |
| Controlled tests declare constants; broader explorations are labeled | Test hypothesis and variant map |
| Creator can film each shot without inventing the strategy | Shot list, script, references |
| Test and review workload fits production and media capacity | Batch count, owners, budget dependencies |

## Raw-footage gate

| Pass/fail condition | Evidence to inspect |
| --- | --- |
| Every required opening, proof shot, and body asset has usable raw coverage | Shot IDs and files |
| Lighting, framing, focus, and audio are usable for the planned crop | Raw previews [S5] |
| Product or interface is legible when its benefit is demonstrated | Proof shots |
| Performance suits the intended audience and preserves approved meaning | Takes versus creator brief |
| Testimonials reflect genuine permitted experience; role-play does not masquerade as a customer result | Script, consent, provenance |
| Footage, music, screenshots, and talent usage permissions cover planned uses | Asset rights record |
| Missing coverage has an explicit pickup request and owner | Strategist review notes |

## Final-edit gate

| Pass/fail condition | Evidence to inspect |
| --- | --- |
| Export ID matches the assigned written and visual hook | Variant map and playback |
| Opening creates relevant attention without concealing the actual promise | First five seconds |
| Body pays off the opening and demonstrates or explains the benefit | Full playback |
| Ad makes sense with sound off, and text remains readable | Muted mobile-sized preview [S10] |
| Captions, graphics, and UI are correct, spelled accurately, and unobstructed | Muted frame review |
| Editing sustains attention while leaving enough time to understand the proof | Full playback and target-audience fit |
| Claims, price, offer, CTA, and destination agree | Approved brief and destination |
| Raw assets and audio rights cover the final execution | Rights record |
| Strategist has approved the final creative and assigned needed revisions | Signed review status |
| Dimensions, duration, crop, filenames, and delivery links meet the brief | Export metadata and file review |

## Learning gate

| Pass/fail condition | Evidence to inspect |
| --- | --- |
| Concept counts, visual variations, copy variants, and format exports are separate | Production inventory |
| Each diagnostic metric has an exact numerator or threshold and denominator | Reporting definitions [S8] |
| Spend, sample counts, period, attribution, audience, and comparison are recorded | Result table |
| Business outcome supports any winning label | Purchase, qualified lead, or trial results |
| Missing or inadequate evidence is marked pending or inconclusive | Decision record |
| Next iteration preserves working elements and names the intended change | Next-week hypothesis [S11] |
| New learning updates the hook library with context, owner, and date | Library entry |

## Common failure modes and fixes

| Failure | Fix |
| --- | --- |
| One person is assigned all three creative jobs | Name the staffing gap, reduce the batch, and assign separate specialists before claiming method-compliant production |
| Creator receives only a product and a request to be viral | Strategist supplies a specific script, visual references, opening actions, and shot list |
| Editor is asked to rescue absent strategy or footage | Return the decision to the strategist and request exact pickup shots |
| Eight captions on one opening are reported as eight visually different ads | Classify them as copy variants and film distinct opening setups |
| Hook attracts attention but body never resolves it | Keep the relevant hook and rebuild the benefit bridge or proof |
| Supposedly authentic testimonial invents personal experience | Use genuine permitted testimony, observable demonstration, or labeled role-play |
| Prospecting script is repeated unchanged for consideration audiences | Address actual questions, objections, and social proof appropriate to the stage [S6] |
| Inspiration turns into copied competitor media | Use original scripts and owned or licensed footage; retain source links for the mechanism |
| A dated trend is described as a guaranteed current winner | Label its date and evidence status, refresh research, and test it |
| Strong watch metrics hide weak purchases or qualified trials | Assess the business objective and post-click journey before assigning a winner |
| Sparse results trigger a confident rewrite | Mark inconclusive, preserve uncertainty, and request comparable evidence |
| Production volume grows faster than review or testing capacity | Bound the batch by the slowest stage and keep acceptance gates intact |
| Friday client delivery is treated as launch approval | Record client review and authorized launch as separate states |
| Publisher promotional numbers are presented as guaranteed outcomes | Attribute reported figures and state their context; do not use them as forecast assumptions |

Final review record: [Stage], [artifact/version], [reviewer], [date], [PASS / FAIL], [failed rows], [fix owner and deadline], [next permitted handoff].
