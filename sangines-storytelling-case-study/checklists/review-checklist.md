# Review checklist

Mark each applicable item PASS or FAIL with a brief reason. Use N/A only when a field is outside the requested scope. The four-part structure reflects [S1]; interview and review checks reflect [S3][S4]; system fit reflects [S2][S5][S6]. Evidence, permissions, and handling of missing data are package safeguards, not claimed proprietary notus rules.

## Deliverable checks

- [ ] PASS / FAIL: The intended customer and relevant problem are identifiable.
- [ ] PASS / FAIL: The story is based on supplied experience or evidence, with invented illustrations clearly labelled.
- [ ] PASS / FAIL: The opening creates investment through a true problem, result, or surprising fact.
- [ ] PASS / FAIL: Any time contrast compares supported starting and ending points.
- [ ] PASS / FAIL: The starting situation explains the client, objective, and obstacle.
- [ ] PASS / FAIL: The familiar barrier appears before unnecessary unusual details.
- [ ] PASS / FAIL: Process stages have noun-based names, concrete actions, and a meaningful sequence.
- [ ] PASS / FAIL: Any turning point or iteration actually occurred.
- [ ] PASS / FAIL: The resulting situation includes supported specifics and qualitative change where available.
- [ ] PASS / FAIL: Metrics retain definitions, units, windows, and relevant denominators.
- [ ] PASS / FAIL: Other contributors are acknowledged when necessary to avoid overstating causation.
- [ ] PASS / FAIL: Broad category-leadership claims are limited to at most one and are supportable.
- [ ] PASS / FAIL: The close truthfully describes ongoing work or a lasting benefit of completed work.
- [ ] PASS / FAIL: The post sounds like the author, and founder review status is recorded accurately.
- [ ] PASS / FAIL: Client names, quotations, confidential facts, and anonymized details stay within permitted disclosure.
- [ ] PASS / FAIL: Internal questions and unresolved placeholders are outside publishable copy.
- [ ] PASS / FAIL: The public method is credited in explanatory material without implying endorsement.
- [ ] PASS / FAIL: No first-party notus performance claim is presented as an expected user outcome.

## Common failure modes and fixes

| Failure | Fix |
| --- | --- |
| Opening celebrates the agency rather than engaging the reader | Lead with the client's recognizable struggle or substantiated change. |
| Impressive number has no timeframe or definition | Return to the evidence record; add context or remove the claim. |
| Client has expertise but the draft never explains the barrier | Show the specific constraint that prevented expertise from producing the desired outcome. |
| Stage names conceal generic activity | Add the action, discovery, and decision inside each stage. |
| Smooth story invents a turning point | Use the actual sequence; omit iteration if none occurred. |
| AI fills gaps with plausible client facts | Ask targeted follow-ups or draft a narrower progress story. |
| Founder sounds like another creator | Return to the founder's speech and review feedback. |
| Follower growth is described as revenue | Keep the measured outcome in its actual category. |
| Ended engagement is described as ongoing | Close on a documented lasting capability or accurate lesson. |
| Interview is assumed to require public podcast distribution | Explain that private conversations can supply posts; publication is optional. |
| Weekly cadence is presented as universal across notus | Distinguish Sanginés's weekly workflow from fortnightly and archival client variants. |
| Case studies become the entire content strategy | Restore tactical, insightful, and personal content around aspirational proof. |
| Likes are treated as qualified demand | Examine audience fit, meaningful conversation, and booking evidence. |
| Two 60% claims are merged | Separate format-level inbound share from personal-profile revenue attribution. |
| Conflicting case-study figures are combined | Attach each to its specific source and period, or omit unresolved values. |
| A CTA is forced into every story | Use a suitable optional next step; preserve the four required narrative moves. |

## Decision

**PASS:** The structure works and all material claims are supported, with any applicable review complete.

**REVISE:** Evidence exists but structure, specificity, voice, disclosure, or review requires correction.

**INSUFFICIENT EVIDENCE:** A completed transformation cannot yet be substantiated. Return the missing-data questions and, if useful, an accurately labelled interview brief or progress story. Do not call an unsupported draft ready to publish.
