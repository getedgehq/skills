# Review checklist

Use this before delivering a finished draft, audit, or campaign. These pass/fail gates operationalize the public method; they are package adaptations. Mark each applicable item Pass or Fail and record a concrete repair for every failure. Mark a conditional item N/A with a reason when the request does not require it. Do not let a high engagement forecast compensate for failed usefulness or evidence checks.

## Core gates

| Check | Pass condition | Fail condition |
| --- | --- | --- |
| Audience fit [S4] [S6] | A specific audience need or trigger is identified. | The idea relies only on novelty, peer approval, or a trend. |
| Research honesty | Evidence and assumptions are distinguished. | Invented research, quotes, or results are presented as real. |
| Business contribution [S3] [S7] | A concrete audience change supports a specific business purpose. | The rationale stops at more revenue, traffic, or vague quality. |
| Standalone usefulness [S1] | Removing URLs and invitations leaves a meaningful insight or specific satisfying experience. | Only a promise, mystery, or list of upcoming topics remains. |
| Defensible context [S1] | Necessary definitions, caveats, and support are local. | Missing context makes the takeaway misleading. |
| Native delivery [S4] | The destination contains the explanation in its appropriate form. | The post, email, or video only directs people elsewhere. |
| CTA quality [S2] [S5] | Any next action is relevant, convenient, and offers additional benefit. | It withholds the central answer or hides the conversion route. |
| Claim discipline | Draft claims are supported and illustrative numbers are labeled. | The copy promises performance or treats hypothetical data as evidence. |
| Scope | Output matches the requested artifact and level of detail. | An audit becomes an unsolicited campaign or a draft is published without instruction. |

Research honesty, claim discipline, and scope are package safeguards. Other rows cite their public-method basis.

## Conditional gates

- [ ] **Idea validation:** Pass if major production has a relevant test or identified information gap. Fail if expensive production rests only on speculation. N/A for a narrowly requested revision with no production decision. [S6]
- [ ] **Recurring premise:** Pass if the program has a distinctive, defensible editorial purpose. Fail if its only premise is a broad topic or a publishing schedule. [S3]
- [ ] **Newsletter experience:** Pass if original tips and curated summaries are useful in the inbox. Fail if links carry all the value. [S3]
- [ ] **Curation breadth:** Pass if source choices serve the premise without habitual dependence on the same few voices. Fail if familiar authors substitute for editorial judgment. [S3]
- [ ] **Derivatives:** Pass if each requested derivative delivers a complete local takeaway. Fail if each repeats the same asset title and URL. [S4] [S6]
- [ ] **Sequence:** Pass if related pieces build knowledge and fit the audience's timing. Fail if a calendar dictates unrelated filler. [S6]
- [ ] **Measurement:** Pass if indicators match the goal, have a review period, and include attribution limits. Fail if click count is the only evidence or correlation is presented as causation. [S2] [S5]
- [ ] **Learning loop:** Pass if feedback has a useful question and a place to inform future research. Fail if reporting records metrics without informing a decision. [S4] [S6]

## Common failure modes and fixes

| Failure | Fix |
| --- | --- |
| Teaser-only promotion | Put one useful conclusion or demonstration in the promotion; let the asset add depth. [S1] |
| Linkless hype | Replace generic excitement with a bounded idea, argument, or recognizable problem. Removing links alone does not create value. [S1] |
| Bullets name topics but explain nothing | Give each bullet its actual answer and enough context to understand it. [S1] |
| Peer-focused or trend-driven idea | Return to customer questions and show why the intended audience cares. [S6] |
| Keyword volume treated as audience proof | Check who needs the information and why; combine search evidence with audience research. [S4] [S6] |
| Same copy everywhere | Rebuild the idea for each destination's native consumption. [S4] |
| Curated newsletter is a link directory | Explain one key insight beside each selected resource. [S3] |
| Useful answer lives only in internal notes | Move it into the publishable artifact; the reader cannot see the brief. [S1] |
| CTA eliminated on principle | Restore a useful, convenient route to the next action after delivering standalone value. [S2] |
| Posting ratio or length treated as a law | Adapt the example to the audience and task; do not promise algorithmic rewards. [S1] [S5] |
| Campaign judged after a week with no tracked sale | Revisit the agreed review period and broader outcome signals. [S2] |
| Attribution uncertainty used to assert success | Report observed movement and its limits, then test the hypothesis further. [S2] [S5] |
| Paid reporting receives all the credit | Consider organic influence and private sharing alongside measurable paid activity. [S2] |
| Historical results become a benchmark | Describe them as the author's examples, not promised outcomes for this campaign. [S3] [S5] |

## Final review record

- **Decision:** [Pass / Revise.]
- **Value remaining without links:** [One sentence.]
- **Failures repaired:** [Item and specific change, or none.]
- **Material assumptions or limits:** [Only those that affect interpretation or use.]

A deliverable passes when all applicable core and conditional gates pass. A finished audit can pass by accurately diagnosing and repairing defects even when the supplied original draft fails. For before-and-after illustrations, see [worked-examples.md](../examples/worked-examples.md).
