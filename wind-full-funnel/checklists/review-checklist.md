# Review checklist

Mark each item PASS or FAIL and add evidence or a specific repair. An item may pass because it is explicitly out of scope with a reason. Unresolved failures affecting delivery make the plan provisional. This reviews a proposed strategy; it does not itself authorize spending or account changes.

## Attribution and evidence

- [ ] PASS / FAIL: Credit and the exact non-affiliation statement appear in the skill entry point.
- [ ] PASS / FAIL: Method claims use source IDs that resolve to actually fetched public material.
- [ ] PASS / FAIL: Podcast/episode descriptions are not presented as transcripts or viewed lessons.
- [ ] PASS / FAIL: Published principles and this package's adaptations are visibly distinguishable.
- [ ] PASS / FAIL: No proprietary budget split, benchmark, paid lesson or automation setting is invented.
- [ ] PASS / FAIL: Historical performance claims are not treated as verified forecasts or causal evidence.
- [ ] PASS / FAIL: Illustrations are labelled invented and contain no fabricated measured results.

## Audience and handoff

- [ ] PASS / FAIL: Every active segment has an observable inclusion event, window, clock anchor and exclusions.
- [ ] PASS / FAIL: Warm familiarity and hot intent are distinguished; recency alone does not determine temperature.
- [ ] PASS / FAIL: Prospecting and cold retargeting are explained when both are used.
- [ ] PASS / FAIL: Stronger-intent movement, purchase exits, expiration and possible clock resets are explicit.
- [ ] PASS / FAIL: Audience sources exist; empty or unreliable pools have a practical fallback.
- [ ] PASS / FAIL: Segment complexity matches volume; logical stages need not become separate ad sets.
- [ ] PASS / FAIL: The operator can verify delivery boundaries or the plan discloses expansion limitations.
- [ ] PASS / FAIL: Retargeting eligibility is not described as a guaranteed individual viewing sequence.

## Creative and destination

- [ ] PASS / FAIL: Cold, warm and hot creative answer different customer questions.
- [ ] PASS / FAIL: Ads contain attention, interest, desire and one clear action appropriate to their job.
- [ ] PASS / FAIL: All benefit claims, reviews and customer proof have supporting evidence.
- [ ] PASS / FAIL: Urgency and scarcity are real; incentives are economically justified.
- [ ] PASS / FAIL: Retargeting adds information instead of repeating one ad indefinitely.
- [ ] PASS / FAIL: The destination matches the promise, offer and next action.
- [ ] PASS / FAIL: Formats fit the assets and current capabilities; historical placement tips are verified before use.

## Economics, tests and delivery

- [ ] PASS / FAIL: Conversion success is defined, including qualification for leads when relevant.
- [ ] PASS / FAIL: Budget arithmetic works, currency is explicit and spend has a stopping boundary.
- [ ] PASS / FAIL: Stage allocation reflects capacity and preserves justified acquisition supply.
- [ ] PASS / FAIL: Missing margins or close rates prevent unsupported profitability promises.
- [ ] PASS / FAIL: Tests state hypothesis, changed variable, business outcome, data requirement and review period.
- [ ] PASS / FAIL: Measurement gaps, conversion lag and attribution conventions are disclosed.
- [ ] PASS / FAIL: Whole-funnel outcomes accompany stage indicators; attributed return is not called incrementality.
- [ ] PASS / FAIL: Scaling requires credible evidence and acceptable economics rather than one conversion.
- [ ] PASS / FAIL: Automation is specified with data conditions, cap and owner or left as manual review.
- [ ] PASS / FAIL: Final actions have owners and deadlines; requested strategy does not silently become live execution.

## Common failure modes and fixes

| Failure | Why it fails | Fix |
| --- | --- | --- |
| Three stage names, one repeated pitch | Labels do not change communication | Write the next customer question and new evidence for each stage |
| All recent engagers called hot | Familiarity does not establish intent | Require a business-specific intent event |
| All warm and hot traffic mixed without rationale | Important objections may be missed | Keep separate briefs; split delivery only if volume and controls justify it |
| Too many tiny retargeting buckets | Sparse delivery and evidence | Consolidate compatible pools, defer empty stages and preserve message jobs |
| Purchasers keep seeing acquisition ads | The message no longer fits their status | Define converter exits and a separate lifecycle purpose |
| Later recency bucket includes early users | Sequencing becomes overlapping repetition | Subtract early eligibility and document clock reset behavior |
| Guaranteed day-by-day ad sequence | Eligibility does not guarantee exposure | Describe planned windows and delivery limitations |
| Permanent countdown or automatic discount | Unsupported urgency or lost margin | Use verified terms, helpful proof or a real bounded offer |
| Scaling based on low form cost | Lead quality and sales are unmeasured | Track qualification, attendance and customers separately |
| Retargeting return treated as causal lift | Existing demand and attribution may explain it | Review aggregate acquisition and use a controlled test where feasible |
| Fixed split or exact automation claimed as Wind's rule | Public settings are not available | Label local assumptions and specify their decision rationale |
| Borrowed brain-hemisphere claim treated as science | A recap is not scientific validation | Keep visual relevance and test creative against outcomes |
| Old tools prescribed without checking availability | Platform behavior changes | Verify current controls before implementation instructions |
| Unseen paid course used as evidence | Provenance is false | Limit claims to fetched public summaries and disclose access gaps |
