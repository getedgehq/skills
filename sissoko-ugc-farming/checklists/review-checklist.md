# Review checklist

Mark each applicable item PASS or FAIL with one sentence of evidence. Use N/A only with an explanation. A brief with a failed outcome, economics, rights, measurement, or ownership check needs correction before it is ready for execution. This is a package quality gate, not a published GATE approval process.

## Method and attribution

- [ ] PASS / FAIL: The deliverable distinguishes published practice, agency-reported results, modeled forecasts, and package recommendations.
- [ ] PASS / FAIL: Every material attributed practice resolves to a fetched [S#] source.
- [ ] PASS / FAIL: Institutional articles are credited to GATE STUDIOS, and personal commentary is attributed only where supported.
- [ ] PASS / FAIL: EUR 1 to 3 CPM and 100M+ monthly views are described as reported claims rather than guaranteed single-brand outcomes.
- [ ] PASS / FAIL: Case metrics retain their source, period, denominator, and scope without merging different client figures.

## Readiness and economics

- [ ] PASS / FAIL: One primary business event, an accountable owner, a budget ceiling, and a decision period are defined.
- [ ] PASS / FAIL: The proposed phase reflects product readiness, including the usual Phase 2 sequencing for prosumer software where relevant.
- [ ] PASS / FAIL: Cost scope includes production, payouts, editing, clipping, operations, tracking, and relevant reserves or explicitly marks exclusions.
- [ ] PASS / FAIL: Clicks, signups, installs, activations, and purchases have distinct definitions; modeled traffic is not reported as observed users.
- [ ] PASS / FAIL: Forecast arithmetic reconciles and contains a downside case that can fail the success threshold.
- [ ] PASS / FAIL: Compensation rates and performance windows are proposed or agreed terms, not an invented universal Sissoko payout formula.

## Supply and distribution

- [ ] PASS / FAIL: Cohort size and sourcing surplus have a reason; less than 15 is clearly an experiment and larger pools justify added coordination.
- [ ] PASS / FAIL: Dedicated accounts have named operators, control and recovery arrangements, cadence, and health review.
- [ ] PASS / FAIL: Replacement capacity, centralized creative review, and payment timing support continuous output.
- [ ] PASS / FAIL: Account warming detail is treated as an unresolved operational choice, not a sourced secret recipe.
- [ ] PASS / FAIL: Creator presentation is truthful, with appropriate relationship disclosure and no fake independent testimony or engagement manipulation.

## Creative and clipping

- [ ] PASS / FAIL: Briefs connect a repeatable format, creator voice, product proof, an audience objection, and a measurable CTA.
- [ ] PASS / FAIL: Paid UGC hook counts, 60/40 mix, and production buffer are labelled adjacent guidance rather than mandatory farm rules.
- [ ] PASS / FAIL: Original assets, clipped derivatives, and platform postings are counted separately with realistic capacity.
- [ ] PASS / FAIL: Clipped material has sufficient context and documented editing and distribution permissions.
- [ ] PASS / FAIL: Platform-specific variants test meaningful differences and retain parent asset identifiers.
- [ ] PASS / FAIL: Paid and product-page reuse is supported by rights and has an explicit funnel purpose.

## Learning and scale

- [ ] PASS / FAIL: Weekly review dimensions include creator, hook, format, platform, and a downstream business event.
- [ ] PASS / FAIL: Comparisons use consistent observation windows and acknowledge portfolio dependence on outliers.
- [ ] PASS / FAIL: Winners get specific development actions; weak formats get a stop, rebrief, or funnel diagnosis.
- [ ] PASS / FAIL: Numerical scale gates derive from user economics and operational capacity; hold and stop conditions name a resolver.
- [ ] PASS / FAIL: Execution actions stay within the user's authorization; a planning brief does not itself authorize creator outreach, contracting, payment, or publishing.

## Common failure modes and fixes

| Failure | Why it fails | Fix |
| --- | --- | --- |
| Promise 100M views from a new cohort | Converts operator claims into a forecast | Label the claim and forecast from explicit assumptions with downside sensitivity |
| Call 3,000 postings 3,000 original videos | Double-counts cross-platform distribution | Separate originals, derivatives, and postings |
| Treat 1% of views as activated users | Omits intermediate conversion losses | Model clicks, signups, and activation separately |
| Apply 30 videos immediately to every prosumer pilot | Confuses discovery with steady-state farming | Use a bounded initial batch after product readiness assessment |
| Choose creators by follower count | Dedicated accounts and native production need different strengths | Vet craft, category fit, product understanding, and capacity |
| Source exactly enough creators | Leaves no choice or replacement path | Build real-offer surplus and maintain backups |
| Multiply accounts when flags appear | Leaves the operational cause unresolved | Hold affected accounts and review permitted practices and account health |
| Order polished generic scripts | Misses platform-native storytelling and useful format hypotheses | Commit to a creative mode and brief product proof in creator voice |
| Clip uncleared podcasts | Blocks legitimate reuse | Clear rights or use owned walkthroughs and creator footage |
| Repeat an outlier unchanged | Produces volume without transferable learning | Identify the hook or payoff and test differentiated adaptations |
| Celebrate cheap reach despite weak activation | Optimizes attention without adoption | Repair the CTA, destination, and onboarding before expanding |
| Pay creators late | Destabilizes the supply pool | Reconcile on schedule with a named payment owner and budget reserve |
| Boost every organic winner automatically | Organic attention may not convert in paid | Check acquisition evidence, permissions, and a separate paid test budget |
