# Review checklist

Evaluate the deliverable against the relevant checks below. Record Pass, Fail, or N/A with a reason and evidence. A plan passes when its requested content is complete and assumptions are visible; launch readiness also requires actual verification of applicable delivery and platform dependencies. Resolve material failures before calling the corresponding stage ready.

## Method fidelity and evidence

- [ ] Pass / Fail: The strategy connects content, distribution, reachable contacts, nurturing, and relevant conversion rather than relying on one ad trick. R3.
- [ ] Pass / Fail: Public method statements cite sources that support them; proposed page designs, cadence, fields, budgets, and thresholds are identified as application choices. R12.
- [ ] Pass / Fail: AMO is credited to AJ Wilcox as acknowledged by Asshauer. R9.
- [ ] Pass / Fail: Named German concepts are retained where helpful and explained in English. R1 to R3.
- [ ] Pass / Fail: No gated templates, inaccessible profile text, unheard audio details, or third-party skill text are presented as researched evidence.
- [ ] Pass / Fail: Reported results have their period and provenance; no universal CPL, ROI timeline, format superiority, or two-week optimization guarantee is asserted. R10.

## Buyer, expertise, and asset

- [ ] Pass / Fail: A clear primary buyer and recognizable Trigger-Symptom anchor targeting and copy. R1.
- [ ] Pass / Fail: The Hauptbotschaft has credible reasoning and an accountable expert. R2.
- [ ] Pass / Fail: The lead magnet solves a bounded problem using shareable, verified knowledge. R4.
- [ ] Pass / Fail: The preview contains usable teaching and the gate unlocks meaningful additional value. R5.
- [ ] Pass / Fail: A five-page preview is justified by content and implementation support, rather than imposed on every asset. R5.
- [ ] Pass / Fail: The ad, preview, capture promise, and delivery agree. R5 and R9.
- [ ] Pass / Fail: Invented examples and hypothetical numbers are labelled clearly.

## Formats and operations

- [ ] Pass / Fail: Thought Leader Ads and Document Ads are distinguished, and format choice follows the funnel job. R6.
- [ ] Pass / Fail: Current eligibility, permissions, and preview controls are either verified for execution or clearly listed as planning dependencies. R6.
- [ ] Pass / Fail: Mobile document readability and the actual gate behavior are checked before launch. R5.
- [ ] Pass / Fail: Capture and asset delivery have owners; the CRM mapping preserves source, variant, fit, stage, and permission state. R3 and R7.
- [ ] Pass / Fail: Download interest is separated from sales readiness, with a defined handoff for explicit requests. R7.
- [ ] Pass / Fail: Nurture messages mostly teach, and the next action matches readiness. R7.
- [ ] Pass / Fail: Contact permission handling and subscription explanation are appropriate to the planned use. R7.
- [ ] Pass / Fail: Content reuse has realistic production and review owners without unnecessary channels. R8.
- [ ] Pass / Fail: Retargeting delivery is not assumed before audience eligibility is known. R11.

## Experiment and decisions

- [ ] Pass / Fail: The hypothesis, cap, period, review point, and stop or scale conditions are explicit. R10.
- [ ] Pass / Fail: Format comparisons use consistent audience, qualification rules, and attribution periods. R9.
- [ ] Pass / Fail: Metrics distinguish total leads, valid ICP contacts, accepted opportunities, and revenue where available. R10.
- [ ] Pass / Fail: Counts accompany rates; zero-denominator measures are marked undefined. R10.
- [ ] Pass / Fail: A small early result is not treated as conclusive proof; uncertainty is stated. R10.
- [ ] Pass / Fail: Poor performance is diagnosed with AMO and operational checks before broad changes. R9.
- [ ] Pass / Fail: Proposed spend, publishing, and direct contact stay within user authorization.

## Common failure modes and fixes

| Failure | Why it matters | Fix |
| --- | --- | --- |
| Corporate introduction instead of useful preview | The buyer cannot judge the asset's value | Teach a relevant diagnostic and demonstrate it before the gate |
| Gate after the final page | Registration unlocks nothing | Add meaningful continuation, shorten preview, or make the asset ungated |
| Generic whitepaper promise | The buyer sees no practical result | Name the bounded problem and the checklist, guide, or tool that helps |
| Five pages treated as a fixed recipe | An experiment becomes an unsupported universal rule | Choose preview length from the learning sequence and verified controls |
| All downloads become SQLs | Interest is confused with buying readiness | Define fit, nurture, and observable readiness with sales |
| Immediate pitch-heavy emails or calls | The system skips trust and demand | Deliver the asset, teach useful lessons, then invite a suitable next step |
| Document Ad described as a personal Thought Leader Ad | Implementation assumptions become wrong | Specify each format separately and verify current setup |
| Low CPL celebrated despite weak fit | Spend grows without usable opportunities | Inspect audience and asset specificity; measure qualified cost |
| Claimed EUR 23.15 leads as a forecast | Another advertiser's early result is substituted for evidence | Label it as reported context or omit it; test local economics |
| Daily new content across every channel | Capacity is consumed without coherent learning | Reuse one expert contribution in selected, maintainable formats |
| Changing audience, hook, and offer together | The test cannot identify what changed the result | Choose a narrow hypothesis and hold other conditions comparable |
| Leads missing from the CRM | Delivery failure looks like creative failure | Repair and verify the integration before spending more |
| Public download descriptions treated as private templates | Attribution exceeds the evidence | Use only visible concepts and label original implementation guidance |
| Research access gaps hidden | Readers cannot judge source reliability | Record inaccessible or unconsumed material and exclude it from claims |
