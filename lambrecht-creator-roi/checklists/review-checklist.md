# Review checklist

Mark every applicable item PASS or FAIL. Use N/A with a reason for genuinely irrelevant items. A missing value can pass only when explicitly disclosed and the recommendation does not depend on it. A failure that changes the decision requires correction or a qualified outcome such as inconclusive or a bounded measurement repair.

## Evidence and attribution

- [ ] PASS / FAIL: Public-method claims cite relevant [S#] entries from the fetched [source register](../references/sources.md).
- [ ] PASS / FAIL: Forecasts, accounting conventions, threshold choices, and proposed contract fields are identified as implementation guidance.
- [ ] PASS / FAIL: No inaccessible transcript, private slide, unheard podcast, or unverified expert formula is claimed as inspected.
- [ ] PASS / FAIL: Self-reported cases remain illustrative and syndicated descriptions are not presented as independent confirmation.

## Business and measurement

- [ ] PASS / FAIL: The decision, target customer, acquisition goal, review deadline, and spending ceiling are explicit.
- [ ] PASS / FAIL: All-in cost includes relevant fees, samples, management, tools, rights, and paid distribution under a disclosed convention.
- [ ] PASS / FAIL: CAC uses distinct new customers; returning-customer orders are separately visible.
- [ ] PASS / FAIL: Net revenue, contribution margin, tax basis, discount treatment, and refunds are consistent or their absence is disclosed.
- [ ] PASS / FAIL: ROAS, revenue-to-total-cost ratio, and contribution ROI have distinct names and denominators.
- [ ] PASS / FAIL: Forecast session CVR is applied to sessions; view-to-order rates are labelled separately.
- [ ] PASS / FAIL: Code and link outcomes are deduplicated, code leakage is assessed, and zero denominators are not reported as zero cost.
- [ ] PASS / FAIL: Estimated and actual views, audience evidence, link integrity, and data provenance are recorded.
- [ ] PASS / FAIL: Attributed sales are not called incremental without suitable evidence; supporting search or traffic signals are not added as extra sales.

## Creator decisions

- [ ] PASS / FAIL: Selection reflects active audience, product fit, engagement quality, and creative credibility rather than fame or follower totals.
- [ ] PASS / FAIL: TKP names the contact denominator and uses comparable costs across options.
- [ ] PASS / FAIL: The brief includes facts, benefits, and CTA with appropriate creator freedom.
- [ ] PASS / FAIL: Soft and hard KPIs are reviewed together without an invented BrandFormance weighting.
- [ ] PASS / FAIL: Cohort age and provisional versus mature findings are explicit; the observation window matches the customer journey.
- [ ] PASS / FAIL: Calendar spending and cumulative placement performance remain separately intelligible.
- [ ] PASS / FAIL: Weak performance is diagnosed for audience, creative, destination, timing, offer, and tracking issues before expansion or termination.

## Commitments and next steps

- [ ] PASS / FAIL: Repeated partnerships and rigid long-term contracts are distinguished.
- [ ] PASS / FAIL: Later placements have separate delivery/yield assumptions and marginal economics, including a credible downside.
- [ ] PASS / FAIL: Staffelrabatte are assessed against effective cost and audience penetration rather than headline savings.
- [ ] PASS / FAIL: Fixed commitments are compared with staged alternatives; exit exposure and proposed review gates are visible.
- [ ] PASS / FAIL: Discount reduction is gradual and instrumented, with a margin and conversion comparison.
- [ ] PASS / FAIL: The recommendation has an owner, spend cap, review date, stopping condition, and observation that would change it.

## Common failures and fixes

| Failure mode | Fix |
| --- | --- |
| Revenue multiple presented as profit ROI | Report ROAS or revenue/cost separately; calculate contribution ROI only with margin evidence |
| Shop CVR multiplied by creator views | Add sessions-per-view, then apply session CVR |
| Cheap TKP treated as an acquisition guarantee | Inspect audience fit, traffic yield, conversion, and Neukunden economics |
| Excellent code sales conceal existing buyers or leaks | Split new versus returning customers, deduplicate orders, show justified adjustments |
| Creator rejected after seven days | Verify execution now, retain cumulative cohorts, defer mature judgment to a justified window |
| Strong engagement used to excuse indefinite losses | Set a capped retest and economic stopping condition |
| Last-click sales treated as the entire effect | Show assisted evidence and limitations without inventing extra attributed revenue |
| First placement duplicated across a year's forecast | Model each placement's changing audience, delivery, and marginal CAC |
| Relationship building used to justify upfront lock-in | Propose staged rebooking and inspect commitment downside |
| Blanket rejection of all repeat creators | Recognize proven partnerships and evaluate later evidence |
| Discount codes removed overnight | Establish baselines, translate evidence cautiously, test gradual reductions with UTMs |
| Show notes treated as a verbatim technical formula | Limit claims to the description and label operational additions |
| General industry averages become guaranteed targets | Use company-specific contribution and comparable historical evidence |

Before delivery, read the completed memo as a spending decision. If its confidence exceeds its evidence or its next action has no limit, it fails review.
