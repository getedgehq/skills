# Negotiation Brief and Round Record

Use this template for preparation, review or debrief. Bracketed fields are intentional fill-in prompts. Replace them with task evidence; use “unresolved” when a material fact is missing. For a short task, compress fields while retaining the boundary, decisive unknowns, package dependencies and next action. These fields are practical adaptations of the public method, not an official simulator form. [S2][S3][S7]

## 1. Assignment and decision

- **Mode:** [Preparation, proposal review, impasse diagnosis or debrief.]
- **Decision needed:** [What must be decided; define the unit of agreement.]
- **Parties and authority:** [Who can decide, what the user can commit, and approvals actually required.]
- **Deadline and next action:** [Real deadline; the next useful question, proposal or review.]
- **Situation diagnosis:** [Auction, single issue, package, internal or repeated relationship; explain what that classification changes.]

Guidance: Diagnose before selecting tactics. If it is an auction, state the known rules and format; do not import a generic optimal bid. [S3]

## 4. Limit, target, opening and concession responses

- **Limit:** [Whole-package boundary, evidence, nonprice constraints and authority.]
- **Target:** [Desired outcome and why it is feasible.]
- **Opening:** [Defensible proposal, including reciprocal conditions.]
- **Likely demand or offer:** [Specific counterpart response.]
- **Planned response:** [Question or conditional concession; state what is received or learned in return.]
- **Offer revision reason, if relevant:** [Actual substantive change, not a tactical pretext.]
- **Credibility check:** [Can the user fulfill every promise? Is an unsupported or extreme claim present?]

Guidance: Do not substitute the opening for the limit. Leave unsupported numeric values unresolved. Check feasibility before turning a proposal into a commitment. [S3][S5]

## 6. Linked package and recommendation

**Package:** [If the user gives these terms, the counterpart supplies these reciprocal terms; name all dependencies.]

**Why the user might accept:** [Value relative to the limit and target.]

**Why the counterpart might accept:** [Supported difference in priorities, or a clearly labeled hypothesis.]

**Feasibility:** [Capacity, authority and implementation requirements.]

**Conditional alternative, if useful:** [A different linked exchange tied to a different constraint; omit if unnecessary.]

**Recommendation:** [Propose, revise, seek information or decline; explain the decisive reason.]

Guidance: Evaluate the whole package. Identify what must be revisited if one reciprocal term is removed. Do not call it mutual gain without showing the mechanism. [S5][S6]

## 8. Process and rehearsal plan

- **Escalation signal:** [Observable counterpressure, retaliation, hostility or misunderstanding.]
- **Reset words:** [Courteous acknowledgment and a question that reopens useful analysis.]
- **Agenda:** [Sequence of the critical questions and linked proposal.]
- **Rehearsal:** [Likely objection, refusal and new fact; state how each changes the plan.]
- **Largest plausible mistake:** [One damaging error and a concrete prevention step.]

Guidance: Preserve the boundary while improving communication. A polished script cannot repair an infeasible package. Rehearse with the team when available. [S4][S5][S7]

## 9. Round record and next-round update

Complete after the real round; during preparation, label this section “pending.”

- **Agreement or non-agreement:** [Exactly what was accepted, including conditions; rejected proposals remain separate.]
- **Unilateral decisions:** [User and counterpart actions made independently.]
- **Open commitments:** [Actual owner, action, deadline and unresolved dependency.]
- **Process observation:** [Specific behavior and its observed effect; identify user, observer or self-assessment.]
- **New information:** [What was learned and which earlier hypothesis changed.]
- **Relationship-state update:** [Changed options, constraints, cooperation and information access.]
- **Next-round adjustment:** [One observable behavior change linked to a consequential habit.]
- **Review status:** [Pass, or remaining material failure with consequence and next action.]

Guidance: Record non-agreement honestly. Debrief behavior as well as outcomes; use the [review checklist](../checklists/review-checklist.md) before presenting the final record. [S2][S4][S7]
