# Pass/fail review checklist

Review the completed brief. Mark each applicable item PASS or FAIL and explain failures. Mark an irrelevant branch N/A with a reason. A failed data-readiness item can lead to a valid repair brief, but cannot be silently treated as a passed performance conclusion. Resolve unsupported recommendations before delivery.

## Method and scope

- [ ] PASS / FAIL: Credits Loomer's public method and avoids implying endorsement, membership access, or authorship by Loomer.
- [ ] PASS / FAIL: Treats the free Master Brief as a dated snapshot and verifies material changing feature assumptions.
- [ ] PASS / FAIL: Applies all eight principles to the reasoning, with exceptions justified rather than suppressed.
- [ ] PASS / FAIL: Separates account facts, hypotheses, source-based advice, and package implementation aids.
- [ ] PASS / FAIL: Uses sources actually fetched, with citations for substantive method claims.
- [ ] PASS / FAIL: Keeps implementation within the user's requested scope and authorization.

## Decisions and structure

- [ ] PASS / FAIL: Defines the business outcome separately from the requested optimization action.
- [ ] PASS / FAIL: Explains the signal's quality, reliability, and connection to business value.
- [ ] PASS / FAIL: Starts with the simplest viable structure and estimates funding and volume for necessary separations.
- [ ] PASS / FAIL: Gives each proposed restriction or customization a proven problem or real business constraint.
- [ ] PASS / FAIL: Distinguishes eligibility controls, suggestions, exclusions, and reporting segments.
- [ ] PASS / FAIL: Requires both private business information and a demonstrated delivery problem before recommending value rules.
- [ ] PASS / FAIL: Considers existing broad warm-audience delivery before adding dedicated remarketing.

## Creative and measurement

- [ ] PASS / FAIL: Proposes substantively different creative concepts with truthful offers and proof.
- [ ] PASS / FAIL: Matches test ambition to budget and avoids forcing equal asset delivery by default.
- [ ] PASS / FAIL: Checks event correctness, browser/server deduplication, and relevant CRM outcomes.
- [ ] PASS / FAIL: Identifies actual attribution settings and differentiates raw events, attributed conversions, customers, and causal lift.
- [ ] PASS / FAIL: Evaluates at the appropriate aggregate unit instead of choosing a winner from low-spend averages.
- [ ] PASS / FAIL: Uses relevant metrics, stable volume, downstream quality, and attribution context to judge meaningfulness.
- [ ] PASS / FAIL: Matches review timing to conversion lag and cohort maturity.
- [ ] PASS / FAIL: Supplies a decision, owner, next evidence, and review or reversal condition.

## Common failure modes and fixes

| Failure | Why it fails | Fix |
| --- | --- | --- |
| Universal one-campaign mandate | Erases distinct objectives and constraints | Treat consolidation as the baseline and fund justified exceptions |
| Many tiny ad sets look sophisticated | Dilutes learning and decision evidence | Estimate events for each unit and consolidate unnecessary splits |
| Cheap clicks imply future customers | Optimizes a proxy rather than the intended outcome | Choose a business-aligned event or explicitly measure downstream value |
| Best low-spend CPA gets all the budget | Assumes cost stays constant as opportunities expand | Assess combined results and test only an evidenced distribution problem |
| Fixed age exclusions based on persona | Confuses typical users with all potential buyers | Keep broad eligibility unless a real constraint or quality problem exists |
| Value rules whenever a segment has higher value | Ignores whether current delivery is materially wrong | Require both gates and use proportional, reviewable adjustments |
| Inherited bid percentages | Treats another account's example as a default | Derive the intervention from local economics and monitor combined outcomes |
| Reported ROAS treated as causal profit | Ignores attribution, repeat transactions, margins, and organic demand | Reconcile revenue and customers; distinguish attribution from incrementality |
| Cheapest CPL wins | Ignores qualification, close rate, and sales lag | Compare matured cohort costs and contribution |
| Dozens of nearly identical ads | Adds production without useful diversity | Change concepts, needs, formats, or persuasion approaches |
| Any bad day means fatigue | Confuses noise or setup defects with exhausted creative | Check meaningful windows, audience mix, and conversion or event problems |
| Never intervene in automation | Turns a preference into dogma | Correct accuracy constraints and use bounded tests for proven problems |
| First conversions equal unique new customers | Substitutes a reporting count for business identity | Reconcile customer records and acquisition status |
| Older strict-age advice overrides later guidance | Freezes the method at an earlier tactic | Prefer newer public clarifications; retain older observations as context |

Do not pass a brief because it uses the right vocabulary. Pass it because the recommendation follows from the observed business problem, the available evidence, and a proportionate intervention.
