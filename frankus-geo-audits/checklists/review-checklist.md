# GEO-Audit review checklist

Mark every item PASS or FAIL and attach the evidence location. Mark a conditional item N/A with a reason. A desk audit can pass with explicitly unmeasured visibility; an incomplete live audit must not be relabeled as complete. Correct failures before delivery or clearly mark the deliverable partial with unresolved items.

## Attribution and evidence

- [ ] PASS / FAIL: Public method credit and non-affiliation are visible where the skill is presented.
- [ ] PASS / FAIL: Published guidance, joint agency work, package conventions, and tool definitions remain distinguishable.
- [ ] PASS / FAIL: Method claims resolve to fetched [S#] sources, with advertorial and gated-recording limits retained.
- [ ] PASS / FAIL: Examples and hypothetical counts are explicitly invented and never presented as real clients or results.
- [ ] PASS / FAIL: No private, paywalled, fabricated, or unsupported material supplies a claim.

## Scope and prompts

- [ ] PASS / FAIL: Brand, category, audience, locale, surfaces, competitors, evidence period, and audit type are declared.
- [ ] PASS / FAIL: Desired category and proposed content match supported capabilities and limitations.
- [ ] PASS / FAIL: Top-Prompts have intent, context, stage, origin, and validation status.
- [ ] PASS / FAIL: Branded, competitor-led, and open discovery cohorts are distinguished; audited-brand prompts do not inflate discovery scores.
- [ ] PASS / FAIL: Sampling and any missing journey stages are explained; similar wording has not artificially inflated coverage.

## Observations and calculations

- [ ] PASS / FAIL: Answer evidence preserves exact prompts, dates, platform/interface, known modes/settings, responses, and citations.
- [ ] PASS / FAIL: Failed, partial, unknown, and unavailable observations are disclosed.
- [ ] PASS / FAIL: Mention, source citation, recommendation, category fit, factual accuracy, and sentiment are separate observations.
- [ ] PASS / FAIL: Cited pages support their associated claims; owned and third-party citations are separated.
- [ ] PASS / FAIL: Metrics disclose definitions, counts, denominator, cohort, period, competitors, and exclusions.
- [ ] PASS / FAIL: Repeated runs and platform differences are visible; unequal conditions are not silently pooled.
- [ ] PASS / FAIL: Missing measurement is shown as not measured or N/A rather than zero.
- [ ] PASS / FAIL: Comparison uses a stable cohort or explains why the prompt-set change prevents a direct trend claim.

## Diagnosis and recommendations

- [ ] PASS / FAIL: Each finding links observations to evidence; suspected mechanisms are labeled hypotheses.
- [ ] PASS / FAIL: Technical conclusions match checks actually performed and distinguish public-page access from crawler-specific behavior.
- [ ] PASS / FAIL: Content proposals answer real questions with substantiated facts, dates, reviewer responsibility, and meaningful constraints.
- [ ] PASS / FAIL: External channel choices reflect audience or observed source relevance, with sponsorship identified.
- [ ] PASS / FAIL: Action priorities reflect harm, relevance, confidence, effort, and dependencies.
- [ ] PASS / FAIL: Every action has an owner, timing, affected assets, and verification criterion; proposed commitments are labeled.
- [ ] PASS / FAIL: Publication, outreach, spend, and form changes are accurately described as proposed or authorized actions.
- [ ] PASS / FAIL: Monitoring assesses answer quality as well as presence and connects commercial outcomes only where evidence supports the link.
- [ ] PASS / FAIL: No guaranteed visibility, universal ranking factor, training inclusion, fixed result timetable, or single-answer causal claim appears.

## Common failure modes and fixes

| Failure | Fix |
| --- | --- |
| High score caused by brand-named prompts | Separate accuracy and discovery; recompute on eligible non-branded responses. |
| A snapshot described as a trend | Label it a snapshot and collect comparable repeat observations. |
| A citation counted as an endorsement | Record source usage and recommendation separately; inspect the cited claim. |
| Fluent answer contains an incorrect category | Fact-check against the ledger and prioritize the conflicting descriptions. |
| Generic article-volume plan | Map important intents to specific pages, evidence, and answer passages. |
| Perfect website presented as sufficient | Inspect relevant external descriptions, reviews, partners, and actual cited sources. |
| Universal instruction to seed top domains | Replace it with audience-specific channel selection and bounded experiments. |
| A Groundingpage or schema promised to solve visibility | Treat it as optional accurate representation; verify access and outcomes separately. |
| Sponsored article treated as independent validation | Disclose sponsorship and keep evidence types distinct. |
| Tool scores combined despite differing definitions | Retain tool definitions or recompute comparable disclosed metrics. |
| Prompt-coverage increase caused by more repeats | State observation counts and compare equivalent sampling. |
| No model access, but invented visibility estimate | Deliver a desk audit and leave model metrics not measured. |
| All failures silently removed | Log attempts and state exclusion rules and failed-run counts. |
| Action has no owner or capacity | Assign a proposed responsible role and narrow the plan to maintainable work. |
| Leads attributed to an edit without evidence | Report self-reported origin or referrals as associations and retain uncertainty. |
| Webinar outline treated as watched recording | Cite only the public outline and disclose the access boundary. |
