Quickstart

Design your first workflow

A useful workflow begins with a precise event and ends with an observable outcome. Use this short guide to sketch the path before wiring it into your runtime.

  1. 1

    Shape the event

    Name the fact in past tense and include only the data a consumer needs. For example, order.created is clearer than process.order.

  2. 2

    Choose a route

    Connect the event type to one focused handler. If several outcomes are needed, make each branch visible instead of hiding unrelated work in one step.

  3. 3

    Handle the work

    Define the intended outcome and what a safe retry means. Keep side effects deliberate and record enough context to diagnose a failure.

  4. 4

    Review the flow

    Read the workflow from trigger to outcome. Confirm that names describe what happened, each step has one responsibility, and errors have somewhere to go.
