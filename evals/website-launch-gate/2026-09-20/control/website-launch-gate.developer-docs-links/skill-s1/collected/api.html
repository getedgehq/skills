Reference

API building blocks

Flux workflows are organized around four small ideas. This overview explains their roles without tying you to a particular runtime.

Implementation note

This repository does not include a published package name or versioned method signatures. Confirm those details from the SDK release before copying production code.

Input

Events

An event describes something that happened. Give it a stable type and the smallest payload that downstream steps need.

{
  "type": "order.created",
  "data": { "orderId": "ord_123" }
}

Direction

Routes

A route connects an event type to the logic that should receive it. Keep routing rules explicit so the workflow remains easy to inspect.

Work

Handlers

A handler performs the application work for a routed event. Design handlers around one outcome and make repeated delivery safe where your runtime requires it.

Recovery

Errors

Treat failures as part of the workflow. Preserve enough context to understand which event failed, where it failed, and whether it can be attempted again.
